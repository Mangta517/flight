# 飞控回归测试

在仓库根目录运行 `python flight_hal/MDK-ARM/tests/run.py`，需要 Python 3 和 GCC。
脚本在系统临时目录编译和运行主机程序，不连接或控制硬件。

测试直接链接生产代码：

- `application_flight.c`、`application_recevie_data.c`、`common_pid.c`：11 个独立进程场景，覆盖初始化/校准失败、飞行中重连、失联减速及 tick 回绕、重新解锁、有效帧年龄、采样失败和阻塞后的检查、完整控制快照、帧校验及事件消费、停机配平门控。
- `my_mpu6050.c`：复位等待上限、HAL ERROR/BUSY/TIMEOUT、失败时保持输出和偏移、重复校准不丢失原偏移。
- 两个工程各自的 `nRF24L01P.c`：STATUS 无完成标志、MAX_RT、tick 回绕、SPI 失败后终止剩余 HAL 调用、模式设置失败传递及正常收发。
- 原有 PID 两个测试函数也会运行；仓库的小型 Unity 统计把断言和测试函数计数混在一起，打印的“4”不是四个测试函数。

应用测试替换 HAL、RTOS 时间、IMU/滤波和压力外设依赖；驱动测试链接真实驱动，替换相应 HAL。
它们验证软件分支和输出，不验证姿态估计精度、电机方向、无线时序或飞行稳定性。

当前失联策略：飞行任务在每轮和阻塞步骤之后按最后有效帧的 80 ms 年龄判断，FAIL 保持到四路零 CCR 写入后退出；按实际 tick 以 83 CCR/s 降低输出。重连不自动解锁，校准只允许 IDLE 且四路电机工作值为零。IMU 读取失败立即停止控制输出，并要求重新启动初始化。

80 ms 是软件帧龄阈值，不是经过实机验证的最坏响应时间；I2C、调度和中断仍影响实际响应。保留原 PID 参数、配平角和通道映射。原生 Keil 构建与这些主机测试均不能替代拆桨台架、传感器故障注入和受控失联测试；本次未烧录或飞行。
